# Desk 42 — Progression Checkpoints

Define these before any playtest begins. Session data records which checkpoints each tester reaches.

## Checkpoints

| ID | Checkpoint | Description |
|----|-----------|-------------|
| CP-01 | Started game | Launched build, reached main menu |
| CP-02 | Completed onboarding | Finished tutorial sequence |
| CP-03 | First claim received | Received first client/claim |
| CP-04 | First claim processed | Completed processing of first claim |
| CP-05 | First full work cycle | Completed one full shift cycle |
| CP-06 | First major system interaction | *(define: e.g., first dial adjustment, first punch card, first internal audit)* |
| CP-07 | Midpoint | *(define: halfway through intended playtest content)* |
| CP-08 | Completion | Reached the intended endpoint of the playtest build |

## Drop-off analysis format

```
XX testers started the build.
XX completed onboarding (CP-02).
XX reached first full work cycle (CP-05).
XX reached the midpoint (CP-07).
XX completed the full experience (CP-08).
```

## Notes

- Update checkpoint definitions to match the actual build content before the pilot.
- Checkpoints should be unambiguous — a tester either reached it or didn't.
- If telemetry is available, record checkpoint timestamps for pacing analysis.
