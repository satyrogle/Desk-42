# Desk 42 — Playtest Cohort Plan

## Cohort structure

| Cohort | Size | Purpose | Build | Status |
|--------|------|---------|-------|--------|
| Pilot | 5–10 testers | Break the validation process, find blockers | v0.1 | Not started |
| A — Baseline | 20–40 testers | Create original product evidence | v0.1 (post-pilot fixes) | Not started |
| B — Validation | 10–30 testers | Validate that a product decision improved the game | v0.2 | Not started |

## Pilot objectives

The pilot cohort's job is to test the testing process itself:

- Installation problems
- Confusing controls
- Inability to understand the premise
- Game-breaking bugs
- Survey problems (unclear questions, missing options)
- Missing telemetry
- Players getting stuck in the same location
- Major discrepancies between intended and actual behaviour

Pilot testers count as genuine external users in the dataset but are clearly identified as the **Pilot Cohort**.

Fix serious problems before wider distribution.

## Cohort A — Baseline metrics

Measure and report:

- Recruitment source breakdown
- Unique testers
- Total sessions
- Completion rate
- Median playtime
- Average playtime
- Drop-off by checkpoint
- Bugs reported
- Survey response rate

Analyse for the strongest repeated problem.

## Cohort B — Validation metrics

Same metrics as Cohort A, plus direct comparison:

- Before/after on the targeted metric
- Statistical significance if sample size allows
- Qualitative comparison of survey responses on the changed area

This cohort answers: **Did the decision actually improve the product?**
